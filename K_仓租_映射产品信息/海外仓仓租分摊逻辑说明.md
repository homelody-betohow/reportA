# 海外仓仓租分摊逻辑说明（K_仓租_映射产品信息）

这份文档用来解释 `A_报表\K_仓租_映射产品信息` 目录里，**海外仓仓租是怎么从仓库账单 → 映射到站点/商品 → 合并进订单统计 → 最终把“无平台部分”分摊到订单上的**。

> 你平时一般只需要运行 `runAll_K.py`，它会按 `K1 → K2 → K3 → K4 → K5 → K6` 顺序执行。

---

## 1. 这套流程最终想得到什么？

最终会在“订单统计”里得到这些列（或更新这些列）：

- **`海外仓仓租费`**：每一行（站点 + 商品ID）对应的海外仓仓租。
- **`所有仓库-无平台-需要分摊的费用`**：一个“总额”，放在表格第 1 行，用于后续分摊。
- **`仓租分摊`**（在 K6 新增）：把上面那个总额，分摊到每一行订单上的金额。
- **`仓租合计`**：`FBA仓租费 + 海外仓仓租费`（K6 计算得到）。

---

## 2. 关键名词解释（用最简单的话说）

- **商品ID**：同一个商品在公司内部的统一编号。
- **SKU**：平台/仓库里常见的产品编码。代码里会把不同来源的 SKU 映射成统一口径的 SKU / 商品ID。
- **站点商品ID识别码**：`站点 + 商品ID` 拼接出来的唯一键，用来把不同表“对齐”合并。
- **无平台（需要分摊）**：有些仓租账单只能算到商品ID，但**不能明确归到具体平台/站点**，这部分会先汇总成总额，最后再分摊到订单行上。
- **分销**：在这套逻辑里，供应商是 `易速` / `智慧谷` 的会被当作“分销”，并且 **分销行不参与仓租分摊**。

---

## 3. 总体流程（K1 ~ K6 做了什么）

### K1 `K1_HY_仓租.py`（鸿羽仓租 → 站点/平台仓租明细）

目标：把“鸿羽”仓库的仓租，从原始明细整理成按 **平台/站点 + 商品ID** 的仓租，并算出“无平台需要分摊”的那一部分。

核心步骤：

1) **合并鸿羽文件**
- 读取目录：`...\仓租\鸿羽\*{shared_date}.xlsx`
- 读取 sheet：`bizWarehouseRentByMonthDetail`

2) **清洗 SKU**
- 去掉前缀：`900008-`
- 去掉一些尾缀（例如 `-MF/-4PX/-UMI/...` 等）

3) **汇总到 SKU 的总仓租**
- 按 `产品代码（SKU）` 分组求和：`产品金额（Product amount）` → 得到 `总仓租`
- 得到 **鸿羽总仓租**：`hy_all_cang_zu = 总仓租.sum()`

4) **SKU 映射（让 SKU 能匹配到商品ID）**
- 用 `仓租-SKU映射.xlsx` 的 sheet `HY仓租-sku` 做一次“儿子 SKU → 统一 SKU”的映射
- 再用 `产品信息库2025.xlsx` 的 `产品信息表` 把 `SKU → 商品ID`

5) **用“库存占比”把商品ID的仓租拆到平台**
- 读取库存周转明细：`...\仓租\{ku_cun_date}库存周转明细.xlsx`，sheet：`各平台SKU库存周转明细`
- 对同一个 `商品ID`：
  - 先算总库存：`sum(在库（可调拨）)`
  - 再算每个平台的占比：`数量占比 = 在库 / 商品ID总在库`
  - 平台仓租：`仓租 = 总仓租 * 数量占比`
- 如果平台是 `无` / `其他`：这部分 `仓租` 直接置 0（因为这被认为是“无平台”）

6) **计算“无平台需要分摊”的仓租**
- `hy_have_site_cang_zu = result_DF['仓租'].sum()`
- `hy_no_site_fen_tan = hy_all_cang_zu - hy_have_site_cang_zu`
- 把这个差额写入一列：`无平台-需要分摊的费用`（只写在第 1 行）

7) **把平台映射成站点，并生成识别码**
- `仓租-站点映射.xlsx`：`平台 → 站点`
- 新增：`站点商品ID识别码 = 站点 + 商品ID`
- 再用 `站点-匹配表.xlsx`：把“原平台列里带站点/别名”的情况映射为统一 `平台`
- 新增：`平台商品ID识别码 = 平台 + 商品ID`
- 重命名 `仓租` → `海外仓仓租费`

产出文件：
- `...\仓租\鸿羽\(处理完成)hy-仓租明细.xlsx`

### K2 `K2_4PX_仓租.py`（4PX 仓租 → 站点/平台仓租明细）

逻辑与 K1 类似，差异点：

- 源文件：`...\仓租\4PX\4PX法国仓-仓租明细-{shared_date}.xlsx`
- 先按 `SKU` 汇总 `应收金额` 得到 `总仓租`
- 直接用 `产品信息库2025.xlsx` 把 `SKU(儿子) → 商品ID`
- 库存拆分平台时，只保留平台：`LM-BTH / LM-TOTO / LM-BC-ls / LM-BC-xj / MANO-EU`
- 同样计算：
  - `px4_no_site_fen_tan = px4_all_cang_zu - px4_have_site_cang_zu`
  - 写入 `无平台-需要分摊的费用` 第 1 行
- 同样做：
  - `平台 → 站点`
  - 生成 `站点商品ID识别码` / `平台商品ID识别码`
  - `仓租` → `海外仓仓租费`

产出文件：
- `...\仓租\4PX\(处理完成)4PX-仓租明细.xlsx`

### K3 `K3_合并_仓租表_站点商品ID识别码.py`（合并所有仓租明细 → “所有海外仓仓租明细”）

目标：把 K1/K2 的结果合并，按 `站点商品ID识别码` 汇总成最终可合并进订单统计的仓租表，并把“无平台总额”汇总出来。

核心规则：

1) 合并：
- 读取：
  - `...\仓租\4PX\(处理完成)4PX-仓租明细.xlsx`
  - `...\仓租\鸿羽\(处理完成)hy-仓租明细.xlsx`
- `merged_df = concat(...)`

2) 额外统计：LM-BC 仓租总和
- `lm_bc_sum = merged_df[原-平台 == 'LM-BC']['海外仓仓租费'].sum()`
- 写入一列 `LM-BC的仓租`（只写在第 2 行，索引 1）

3) 汇总“所有仓库无平台总额”
- `all_fen_tan_cang_zu = merged_df['无平台-需要分摊的费用'].sum()`

4) 按 `站点商品ID识别码` 分组汇总仓租
- `海外仓仓租费` 求和
- 其它字段（SKU/商品ID/站点/平台/平台商品ID识别码）取 first

5) 再把 `商品ID → SKU` 映射一次（确保 SKU 字段存在）
- `产品信息库2025.xlsx`：`商品ID → 产品编码`

6) 过滤无效行（只保留“有效站点、且海外仓仓租费不为 0”）
- 站点不能为空、且不等于 `无/其他`
- `海外仓仓租费 != 0`

7) 把两个“总额”写到第一行，留给后面分摊
- `所有仓库-无平台-需要分摊的费用`：第 1 行写入 `all_fen_tan_cang_zu`
- `LM-BC的仓租`：第 1 行写入 `lm_bc_sum`

产出文件：
- `...\仓租\(处理完成)所有-海外仓-仓租明细.xlsx`

### K4 `K4_合并_分摊_订单统计.py`（仓租表合并进订单统计 + 若干站点“替换归并”）

目标：把“所有海外仓仓租明细”合并进订单统计，并对一些特殊站点做“替换/归并”，让仓租能落到更合理的站点行上。

#### 4.1 合并逻辑（最核心）

- 订单统计输入：`(已完成-15)订单统计-{shared_date}.xlsx`
- 仓租输入：`(处理完成)所有-海外仓-仓租明细.xlsx`
- 合并键：**`站点商品ID识别码`**
- 合并方式：左连接（left join）
- 然后把“仓租表里存在，但订单统计里没有”的行也追加进来（避免仓租丢失）
- 合并完：
  - `海外仓仓租费` 空值补 0
  - 新增列 `所有仓库-无平台-需要分摊的费用`，在第 1 行写入仓租表第 1 行的总额

#### 4.2 特殊规则：`LM-BC` 仓租分给 `-BC-ls` 与 `-BC-xj`

代码逻辑写得很明确：

- 取 `lm_bc_sum`（来自仓租表第一行 `LM-BC的仓租`）
- 找出站点后缀是 `-BC-ls` 或 `-BC-xj` 的行
- **先把 `lm_bc_sum` 平分成两半**：每个 suffix 分到 `lm_bc_sum/2`
- 再在 suffix 组内，按销量占比分摊到每行：

\[
每行海外仓仓租费 = \frac{lm\_bc\_sum}{2} \times \frac{该行销量}{该suffix总销量}
\]

并用这个结果**覆盖**这些行的 `海外仓仓租费`。

#### 4.3 特殊规则：站点替换 + 仓租累加（`replace_site_with_rent`）

这段逻辑的目的：有些“站点名”在订单统计里不稳定/不标准，导致合并后仓租落在“孤岛站点”上。
所以代码会把指定站点的行，**改投**到同平台里“最合理的其它站点”上，并把仓租累加进去。

替换调用顺序（代码里写死）：

- 平台 `MANO-EU`：站点 `MANO-FR`
- 平台 `REAL`：站点 `REAL-FB`
- 平台 `LM`：站点 `LM-BTH`
- 平台 `LM`：站点 `LM-BC-ls`
- 平台 `AMAZON-EU`：站点 `AMAZON-DE`

替换规则（通俗版）：

- 先在同平台中，找“站点里包含相同结尾关键词”的其它站点，按**站点总销量**从大到小排序，得到候选列表 `replacements`
  - 对多数平台：用 `site` 的最后一段当关键词（例如 `REAL-FB` 的关键词是 `FB`）
  - 对 `MANO-EU`：关键词就是整段 `MANO-FR`
- 对所有 `站点 == site` 的行，逐行处理：
  - 依次尝试把它的仓租“并到”候选站点上：
    - 拼一个新 key：`new_id = new_site + 商品ID`
    - 如果原表里已经存在 `站点商品ID识别码 == new_id` 的行：把该行 `海外仓仓租费 += 当前行海外仓仓租费`，然后当前行最终会被删除
  - 如果所有候选都找不到匹配行：就用候选列表的第 1 个站点创建一条“替换后的新行”（站点/识别码换掉），保留仓租
  - 不管有没有匹配，原 `site` 那些行最终都会删掉

产出文件：
- `(已完成-16)订单统计-{shared_date}.xlsx`

### K5 `K5_映射_产品信息(月报，手动操作这里，MANO-MF的仓租).py`（补产品信息：分类/产品状态/供应商/运营模式）

目标：为后续“分销识别”“分摊过滤”准备字段，并提示你做一些人工检查。

核心映射：

- `商品ID → 二级分类 / 三级分类`（产品信息库2025.xlsx）
- `商品ID → 产品状态`：
  - 平台包含 AMAZON：用 `AMZ新老品`
  - 非 AMAZON：用 `本土平台新老品`
- `SKU → 运营模式 / 供应商`（`BTH_ALL_SKU_DETAIL_PATH` 的 `基础数据维护`）
- 对 `产品状态` 为空的，再用 `信息-映射.xlsx` 的 `产品状态` sheet 补一次

额外规则（写死）：

- SKU 以 `U88` 开头：`产品状态=新品`，二/三级分类=其他
- SKU 以 `-NW` 结尾：`产品状态=不保留老品`
- SKU 以 `25` 或 `SN25` 或 `207` 开头：`供应商=智慧谷`
- `供应商` 为 `易速/智慧谷`：`产品状态=分销`，并把二/三级分类改为 `分销`，运营模式改为 `自运营`

产出文件：
- `(已完成-17)订单统计-{shared_date}.xlsx`

> 这一步脚本会在控制台提示你：检查 `产品状态/分类/供应商/运营模式` 是否都有值，不全的需要你手动补。

### K6 `K6_处理分销_分摊_仓租.py`（最终分摊：把“无平台仓租总额”摊到订单上）

这是你问的“分摊逻辑”最核心的一步。

#### 6.1 分销行的处理（先把“分销”统一口径）

在 `(已完成-17)订单统计` 基础上，脚本会把“分销”相关字段统一成固定值：

- 如果 `供应商` 是 `易速/智慧谷`：
  - `产品状态/二级分类/三级分类 = 分销`
- 如果 `供应商 == 智慧谷`：
  - `采购成本/订单采购成本/重发采购成本/二次上架采购成本 = 0`
- 如果 `产品状态 == 分销`：
  - `运营模式=自运营`，二/三级分类=分销
  - `头程/关税/派送费 = 0`

#### 6.2 仓租分摊公式（非常重要）

1) 先取“要分摊的总额”：

- `total_cost = sum(所有仓库-无平台-需要分摊的费用)`

> 注意：这个列在 K4 才写入订单统计，并且通常只有第 1 行有值，其它行是空。`sum()` 的结果就是要分摊的总额。

2) 决定谁参与分摊：

- **参与分摊的行 = `产品状态 != 分销` 的所有行**

3) 分摊方式：

- **平均分摊（每行同样金额）**

\[
每行分摊额 = \frac{total\_cost}{参与分摊的行数}
\]

4) 写回表格：

- 新增列 `仓租分摊`：
  - 先全表初始化 0
  - 再对 `产品状态 != 分销` 的行填入 `allocation_per_row`
- 把原来的 `海外仓仓租费` 先改名：`原-海外仓仓租费`
- 新的 `海外仓仓租费`：

\[
海外仓仓租费 = round(原海外仓仓租费 + 仓租分摊, 2)
\]

5) 计算仓租合计：

\[
仓租合计 = round(FBA仓租费 + 海外仓仓租费, 2)
\]

产出文件：
- `(已完成-18)订单统计-{shared_date}.xlsx`

---

## 4. 一句话总结“海外仓仓租分摊逻辑”

1) 先把仓库账单变成 “**站点 + 商品ID** 的仓租”（能归属的部分用库存占比拆到平台/站点）  
2) 剩下 **不能归属到平台/站点** 的仓租，汇总成一个总额 `所有仓库-无平台-需要分摊的费用`  
3) 在订单统计里，把这笔总额 **平均分摊到所有“非分销”行**，并加回 `海外仓仓租费`

## 5. 你运行时应该怎么用（推荐流程）

- 直接运行 `runAll_K.py`。
- 重点关注 `K5`：脚本会提醒你**手动检查/补齐**产品状态、分类、供应商、运营模式等字段。
- 如果你是月报场景，`K5` 里还有一条提示：`AMAZON-UK` 的仓租可能需要人工挪到 `AMAZON-DE`（脚本只提示，不会自动做）。
