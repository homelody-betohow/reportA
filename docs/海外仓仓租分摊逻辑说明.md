# 海外仓仓租分摊逻辑说明

说明 `modules/K_storage_fee_product_info` 下**新链路**：仓库账单如何经库存周转拆到销售平台、再按订单销量落到站点，并入订单统计，最后把「无平台」费用摊到非分销行。

> 旧脚本（`K1_HY_仓租.py` / `K2_4PX_仓租.py` / `K3_合并_仓租表_站点商品ID识别码.py` / `K4_合并_分摊_订单统计*.py`）仍保留在目录中，**日常请按本文新链路执行**。  
> `runAll_K.py` 目前仍按文件名排序跑旧脚本，新链路请按下文「推荐执行顺序」手动跑。

---

## 1. 最终要得到什么

在订单统计（已完成-18）上形成：

| 列 | 含义 |
|---|---|
| `海外仓仓租费` | 行级海外仓仓租（含无平台均摊部分） |
| `原-海外仓仓租费` | K6 分摊前的行级仓租 |
| `所有仓库-无平台-需要分摊的费用` | 无平台总额（通常只写在第 1 行） |
| `仓租分摊` | 无平台总额按行均摊的金额 |
| `仓租合计` | `FBA仓租费 + 海外仓仓租费` |

中间还会写出：`站点商品ID识别码`、`平台商品ID识别码`、产品属性（运营模式 / 供应商 / 分类 / 产品状态）等。

---

## 2. 名词

- **商品ID**：内部统一型号（`product_sku.product_uid`）。
- **SKU**：标准产品编码（`product_sku.product_sku`）；仓租侧仓库 SKU 经 `product_sku_mapping` 映射得到。
- **销售平台**：库存周转里的平台标签（如 `MANO-EU`、`LM-BTH`）；K1_0 先按此拆仓租。
- **平台 / 站点**：订单统计口径；K1_3 把销售平台映成订单「平台」，再按订单「站点」拆费。
- **站点商品ID识别码**：`站点 + 商品ID`，K1_4 与订单统计合并的主键。
- **平台商品ID识别码**：`平台 + 商品ID`。
- **无平台**：无法落到有效销售平台/站点的仓租，先汇总，K6 再均摊到非分销行。
- **分销**：供应商为 `易速` / `智慧谷`（或产品状态为分销）的行；**不参与**无平台仓租均摊。

---

## 3. 总览

```text
K0 库存周转（snapshot_market_turnover → Excel）
    ↓
K1_0_HY / K1_0_4PX（仓库账单 → 按销售平台库存占比拆费）
    ↓  (平台分摊)*.xlsx
订单统计 (已完成-15)（J1 日报 / J3 月报）
    ↓
K1_3 合并两仓 + 按订单销量阶梯拆到站点
    ↓  (平台分摊)所有-海外仓-仓租明细.xlsx
K1_4 按识别码并入订单统计 → (已完成-16)
    ↓  （月报：C2_ManoRent合并 写 FBA仓租费）
K5 映射产品信息 → (已完成-17)
    ↓
K6 分销收尾 + 无平台均摊 → (已完成-18)
```

核心原则：

1. **能归属平台的**：用 K0「可售库存-可调」占比拆到销售平台（排除 `无` / `其他` / `ALL` 作分母）。
2. **能归属站点的**：用订单销量阶梯 D，尽量把费用留在同一销售平台内。
3. **仍无法归属的**：进「无平台」，最后在订单上对非分销行**平均分摊**。

## 4. 各步骤说明

### 4.1 K0 `K0_库存周转.py`

从库表 `snapshot_market_turnover` 生成库存动销 Excel，供 K1_0 使用。

- 输出：`…\仓租\{ku_cun_date}库存动销明细.xlsx`
- K1_0 读取 sheet：**各平台商品ID周转明细**
- 关键列：`销售平台`、`商品ID`、`可售库存-可调`

---

### 4.2 K1_0_HY / K1_0_4PX（仓库 → 销售平台）

| | HY | 4PX |
|---|---|---|
| 脚本 | `K1_0_HY_仓租.py` | `K1_0_4PX_仓租.py` |
| 账单 | `…\仓租\鸿羽\*{shared_date}.xlsx` | `…\仓租\4PX\4PX法国仓-仓租明细-{shared_date}.xlsx` |
| 金额 | `产品金额` 按产品代码汇总 | `应收金额` 按 SKU 汇总 |
| 映射 | `product_sku_mapping`（HY / warehouse）→ `product_sku` → `product_uid` | 同理（4PX / warehouse） |
| 产出 | `(平台分摊)HY-仓租明细.xlsx` | `(平台分摊)4PX-仓租明细.xlsx` |

**分摊规则（两仓相同）：**

1. 清洗：HY 仅去前缀 `900008-`（不再剥业务尾缀）。
2. 仓库 SKU → 标准 SKU / 商品ID（DB）；映射缺失则插入待补全行并中止，可先跑 `upProductMapping.py`。
3. 对同一商品，用 K0 有效销售平台的 `可售库存-可调` 占比拆 `海外仓仓租费`：
   - 有效平台：排除 `无` / `其他` / `ALL`（这些库存不进分母）。
   - 仅当该商品**没有任何有效平台库存**时，整笔进 Sheet2「无平台-仓租费用」。
4. 输出双 Sheet：
   - Sheet1 `平台分摊`：SKU / 商品ID / 销售平台 / 可售库存-可调 / 海外仓仓租费；第 1 行写本仓无平台总额。
   - Sheet2 `无平台-仓租费用`：明细 + 原因。

> 此步只拆到**销售平台**，不到订单「站点」。

---

### 4.3 K1_3 `K1_3_合并仓租+站点分摊.py`（合并 + 拆到站点）

**输入**

- `(平台分摊)4PX-仓租明细.xlsx`、`(平台分摊)HY-仓租明细.xlsx`
- `(已完成-15)订单统计-{shared_date}.xlsx`（销量维度）

**处理**

1. 合并两仓 Sheet1，按 `商品ID + 销售平台` 汇总仓租。
2. 销售平台 → 订单「平台」：`map_region_to_platform`（DB）；未命中回填原文。（不再使用本地平台字典。）
3. **站点分摊阶梯 D**（费用尽量留在该平台内）：

| 级别 | 条件 | 做法 |
|---|---|---|
| L1 | 该商品在该平台有站点销量 | 按该商品各站点销量占比 |
| L2 | 否则该平台有站点总销量 | 按平台内站点总销量加权 |
| L3 | 否则订单里该平台有站点列表 | 站点均摊 |
| L4 | 否则 | `PLATFORM_TO_SITE` 默认主站（未收录则恒等） |
| L5 | 仍无法落点 | 进「无平台-仓租费用」 |

4. 生成识别码：`站点商品ID识别码 = 站点+商品ID`，`平台商品ID识别码 = 平台+商品ID`。
5. 写出前去掉 `|海外仓仓租费| ≈ 0` 的行。
6. 无平台总额 = 两仓原无平台 + L5；写在 Sheet1 第 1 行「无平台-仓租费用」。

**输出**

- `…\仓租\(平台分摊)所有-海外仓-仓租明细.xlsx`
  - Sheet1 `平台分摊`
  - Sheet2 `无平台-仓租费用`

---

### 4.4 K1_4 `K1_4_合并订单统计(月报-需执行ManoRent).py`（15→16）

**输入**：`(已完成-15)` + K1_3 仓租明细  

**处理**

1. 按 `站点商品ID识别码` left merge `海外仓仓租费`。
2. 仓租有、订单无的识别码行追加（空识别码不追加）。
3. 透传无平台：K1_3「无平台-仓租费用」→ 结果列「所有仓库-无平台-需要分摊的费用」（第 1 行）。

**明确不做（相对旧 K4）**

- 不做 LM-BC 总仓租对半分（站点已在 K1_3 按销量拆好）。
- 不做壳站点替换（`MANO-FR` / `AMAZON-DE` / `LM-BTH` 等）。  
  旧链路先落到壳站点再归并；K1_3 已按订单真实站点分摊，再替换会误删订单行并二次挪费。

**输出**：`(已完成-16)订单统计-{shared_date}.xlsx`

**月报**：跑完 K1_4 后执行 `C2_ManoRent合并.py`，把 MANO 仓租写入同一份 16 的「FBA仓租费」，再进 K5。

---

### 4.5 K5 `K5_映射_产品信息.py`（16→17）

为 K6 准备分销/分类口径：

| 字段 | 来源 |
|---|---|
| 运营模式 / 供应商 | DB `product_sku`（`ops_model` / `supplier_abbr`；匹配前剥 `-NW`） |
| 二级 / 三级分类 | `产品信息库2025.xlsx` |
| 产品状态 | 亚马逊用 `AMZ新老品`，其它用 `本土平台新老品`；空值再用桌面 `信息-映射.xlsx` |

业务规则（摘要）：U88→新品；`-NW`→不保留老品；`25/SN25/207`→供应商智慧谷；易速/智慧谷→分销并改运营模式/分类。

**输出**：`(已完成-17)`。请人工检查供应商、运营模式、产品状态、分类是否齐全。

月报提示：若 `AMAZON-UK` 只有仓租，需人工挪到 `AMAZON-DE` 后删 UK（脚本只提示）。

---

### 4.6 K6 `K6_处理分销_分摊_仓租.py`（17→18）

1. **分销收尾**（供应商→分销规则已在 K5；此处不再重复覆盖产品状态，以免盖掉人工修正）  
   - 智慧谷：采购相关成本置 0  
   - 产品状态=分销：运营模式=自运营，二/三级=分销；头程/关税/派送费=0  

2. **无平台均摊**  
   - 总额：取「所有仓库-无平台-需要分摊的费用」第 1 个非空值  
   - 参与行：`产品状态 != 分销`  
   - 每行：\( \text{仓租分摊} = \dfrac{\text{总额}}{\text{参与行数}} \)（不做逐行 round，避免累计误差）  
   - \( \text{海外仓仓租费} = \text{原-海外仓仓租费} + \text{仓租分摊} \)  
   - \( \text{仓租合计} = \mathrm{round}(\text{FBA仓租费} + \text{海外仓仓租费},\ 2) \)

**输出**：`(已完成-18)订单统计-{shared_date}.xlsx`

## 5. 一句话总结

1. **K0 + K1_0**：账单按库存占比拆到销售平台；无效应进无平台。  
2. **K1_3**：合并两仓，按订单销量阶梯拆到真实站点；写识别码。  
3. **K1_4**：按识别码挂到订单；透传无平台总额。  
4. **K5 / K6**：补产品属性；无平台总额均摊到非分销行，得到最终海外仓仓租与仓租合计。

## 6. 推荐执行顺序

先配置 `config/A0_set_date.py`（`folder_name` / `shared_date` / `ku_cun_date`）。

```text

# 或：modules/J_amz_storage_fee/monthly/J3_合并_订单统计.py

# 合并到站点 → 并入订单
python modules/K_storage_fee_product_info/K1_3_合并仓租+站点分摊.py
```

核对提示（K1_3 控制台）：

\[
\text{站点分摊海外仓仓租费} + \text{无平台} \approx \text{两仓平台分摊合计} + \text{两仓原无平台}
\]

## 7. 与旧链路差异（速查）

| 点 | 旧链路 | 新链路 |
|---|---|---|
| SKU / 商品ID | Excel 映射表 | `product_sku_mapping` + `product_sku` |
| 库存来源 | 库存周转明细 Excel（手工） | K0 ← `snapshot_market_turnover` |
| 平台拆分 | 库存平台占比 → 再映壳站点 | K1_0 销售平台占比；K1_3 订单站点阶梯 |
| 合并进订单 | K4：LM-BC 对半分 + 壳站点替换 | K1_4：仅识别码 merge |
| 运营模式/供应商 | BTH全部SKU明细.xlsx | `product_sku.ops_model` / `supplier_abbr` |
